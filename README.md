# JTH job recommendation — IIC3633 final project

Job recommendation on **JTH (Job Tracking History)**, a 7-year dataset of recruiter-curated
candidate–job processes in France (Romero, Millet & Behar, RecSys '26).
Course: IIC3633 Sistemas Recomendadores, PUC Chile, 2026-2. Group 5.

- Paper: <https://doi.org/10.1145/3773078.3831846>
- Official code: <https://github.com/Aunsiels/JTH> (git submodule in `external/JTH`)
- Data: <https://zenodo.org/records/21390581> (CC BY-NC 4.0, non-commercial research only)

Working with a coding agent? Read [`AGENTS.md`](AGENTS.md) first.

## Setup

Requires [uv](https://docs.astral.sh/uv/) and git. Python 3.12 is pinned in `.python-version`
and uv installs it if needed.

```bash
git clone --recurse-submodules <this repo>   # or: git submodule update --init
uv sync                                      # Python env + this package (src/jth)
uv run python scripts/download_data.py       # -> data/raw/ (md5-checked)
bash scripts/run_upstream.sh                 # official split + baseline predictions (~50 min)
WITH_SLOW=1 bash scripts/run_upstream.sh     # + logistic regression (~17 min more)
```

Data, prediction files, figures and LaTeX tables are not versioned. The data comes from
Zenodo (checksummed), the predictions (~100 MB) are regenerated by `run_upstream.sh`, and
the figures and tables by the scripts in the table below.

## Task and evaluation protocol

Every number we report uses the official split and the official evaluator
(`external/JTH/code/utils/evaluator.py`). Main task: **c2j**, recommending jobs to a candidate.

- **Interaction**: one candidate–job process, dated by its earliest stage. Any process counts
  as positive, whatever stage it reached.
- **Split**: chronological 80/20. Test = 2024-03-23 → 2025-04-21.
- **Query**: a (candidate, day) pair with at least one process in test. There are 8,341 queries
  for 8,458 test interactions, because when a candidate starts several processes on the same
  day the evaluator keeps only one of them as the relevant job.
- **Ranking**: each model returns its top-1000 jobs per query. Jobs created after the query day
  are dropped before scoring.
- **Metrics**: MRR (main) and NDCG@10. Warm = the candidate had an earlier interaction
  (in train or earlier in the test stream); cold = first appearance.

Our own evaluator vs the official one:

| | official | ours |
|---|---|---|
| ranking depth | top-1000 lists | full catalog |
| ties in score | sorted by id (or shuffled, per script) | broken uniformly at random (seeded) |
| several targets for the same query and day | last one overwrites the others | one query with several relevant targets |
| split (`--split test`) | cut at a row index (one day can fall on both sides) | cut at a day boundary |

On the official split, our Popularity, Pop + recency and Recency reproduce the official
code to within 0.001 MRR in c2j (see `results/comparison.md`).

## Data notes

- Pseudonymised, with timestamps noised by ±5 days (order preserved).
- Sensitive LLM-inferred attributes (`llm_sex`, `llm_nationality`, `llm_age_bucket`, …) are not
  used as model features.
